# MIS205 课程项目与全栈重构说明（脱敏版）

## 项目概述

本项目最初由三名成员共同完成，目标是设计一个供高校学生与活动组织者使用的校园活动报名系统。团队共同参与需求梳理、关系数据库设计和前端原型开发，并同意将脱敏版本用于公开展示。

## 原始课程原型

课程阶段使用原生 HTML、CSS 和 JavaScript 实现了注册、登录、活动筛选、活动管理及报名交互。该版本的数据保存在浏览器内存中，主要用于验证需求与页面流程，不具备真实后端持久化和服务端权限控制。

## 当前个人重构

本仓库的 `v0.2` 由仓库维护者在课程项目之后独立完成全栈重构：

- 使用 Supabase Auth 管理注册、登录和会话；
- 将人员、用户资料、活动和报名关系迁移至 PostgreSQL；
- 使用 Auth 触发器验证校园人员三字段身份，并自动创建 profile；
- 使用 RLS 与显式 Data API grants 控制行级和表级权限；
- 使用 PostgreSQL RPC 与行锁执行报名和取消，避免并发超额；
- 使用 Vite 管理前端开发、生产构建和依赖；
- 增加匿名 Data API 冒烟测试和浏览器页面验证。

因此，对外介绍时应分别表述“三人共同完成课程原型”和“个人完成 Supabase 全栈重构”，不能把整个全栈版本笼统写成个人从零完成，也不能把原始原型描述为已接入后端。

## 业务流程

1. 校园人员使用姓名、学号或工号、校园邮箱完成私有白名单匹配。
2. 验证通过后，Auth 账号与 `profiles` 资料自动建立一一关联。
3. 匿名访客可以查看已发布活动；登录用户可以查看本人草稿。
4. 已验证用户可以创建、编辑和删除本人活动。
5. 用户通过数据库函数报名或取消报名，系统在事务内锁定活动并维护报名人数。
6. 活动组织者只能读取本人活动关联的报名记录，普通用户只能读取自己的报名记录。

## 数据模型

- `private.school_personnel`：校园人员白名单，仅供注册触发器访问。
- `public.profiles`：已验证用户资料，与 Supabase Auth 用户一一对应。
- `public.events`：活动信息、组织者、状态、容量和已报名人数。
- `public.registrations`：以活动和用户组成联合主键的报名关系。
